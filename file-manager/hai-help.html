HAI is a rule engine for Hubitat, an alternative to Rule Machine, built so a rule can be read, checked and trusted before it runs. Key features
• A modern, interactive rule editor: drag and drop steps, cut, copy and paste between rules, undo, search, every step in plain English, and live device values beside each condition.
• Checked before it runs: missing devices, commands a device does not offer and steps that can never run are found when you save.
• Simulate a rule, and see exactly what differs from the copy on the hub before you put it there.
• Backups and restore: a nightly copy of every rule, compared and restored from the editor.
• RM migration (optional): test copies of your Rule Machine rules in HAI, switch them over one at a time, and switch back whenever you like.
• AI Rule Assistant (optional): describe a rule in your own words and Claude drafts it, on your own key, with a spending limit; drafts go through the same checks.
• Run rules from anywhere: a dashboard tile, a phone shortcut, another hub or another app can start a rule or set a value, through a web address HAI gives you. Benefits
• Faults are caught at the desk, not discovered when a light fails to come on.
• Rules are explained in plain speak.
• Controlled testing and migration from Rule Machine, and back.
• HAI sends nothing off the hub except what your own rules ask for and, if you add an AI key, what you ask it to draft. User documents

Let other things run your HAI rules: a dashboard button, a phone shortcut, another hub, or another app on this hub such as Rule Machine. They can start, stop, pause or resume a rule. They can't create, change or delete one. Technical: other apps send a request as a hub location event, and HAI answers with the rule list or the result. Off means HAI refuses every request. Each request from another app must carry this token, or HAI ignores it and says so once in the log. Paste it into the app that sends the requests. With the HAI Rule API library, that is its HAI API token setting. Off: the web address does nothing. Turn it on to show it. Anyone who has this address can run your rules, so treat it like a password. Don't post it in the community or in screenshots. Technical: open the address as it is to list your rules and their ids. To act on one, put the rule id and an action after /endpoint/rules and before the ?: /endpoint/rules/<rule id>/run. The other actions are /stop, /pause, /resume, /trigger, and /boolean/true or /boolean/false for the rule's Private Boolean. /endpoint/variables/<name>/<value> sets a hub variable, but only one ticked under Approved hub variables. Works on your home network only. The levels behind the words the rule editor offers for conditions: how dark is dark, how hot is hot. The values below are generic starting points: change them to suit your own climate and preferences. Rules follow these settings: after a change, every rule that uses a changed word is updated to it, one at a time, each as a new version. A running rule stays running and a stopped one stays stopped. Light is read from a light sensor (illuminance), so artificial light and dull weather count. Weather words read an OpenWeatherMap device. Hubitat has a built-in OpenWeatherMap driver: create a Virtual Device with that driver, enter your OpenWeatherMap API key in it, then choose it here. Choosing it here also approves it for HAI, under Approved devices. With none chosen, the editor uses an approved device that reports temperature, wind speed and the weather. Connect an AI assistant, such as Claude Desktop, so you can describe a rule in a conversation and have it written for you. The assistant can see your approved devices and your rules, and send HAI a rule to check. HAI checks it, reads it back in plain English, and keeps it as a draft in the editor for you to review. The assistant can't turn a rule on or run one; only you can, in the editor. Off: nothing can connect. Turn it on to show the address to give your AI assistant. Press Done to create the address. Technical: add this address as an MCP server (Streamable HTTP) in your AI client. It offers hai_describe (the rule format and your devices), hai_propose_rule (check, read back and simulate a draft), hai_get_rule and hai_render_rule. Works on your home network only. It uses your AI client's own account, not the API key above. Use this if you think someone has a link to HAI they should not have, for example from a screenshot, a shared message or an old phone. Pressing the button changes every HAI link at once, so the old ones stop working. Your rules keep running as before. This does not change the AI API key under AI token and cost management. It changes only the links and token used by apps and pages on your home network. What stops working until you update it: bookmarks and saved links to the HAI editor, editor pages you already have open, and any dashboard, shortcut, AI assistant or other app that controls HAI. What you need to do after changing it: open the editor from this page again, and copy the new links and token shown on this page to wherever you use them. Technical The editor, end point and MCP addresses, the API token for other apps and the Rule Machine Migration address all change at once. After you press it, editor tabs that are open, saved links and bookmarks, dashboard buttons and shortcuts that use the end point address, your AI assistant's MCP address, and other apps' API token stop working. Copy the new addresses and token from this page to where you use them. Rule apps receive their new editor link automatically. The Claude API key is a separate credential and is not rotated. Diagnostics are on. They turn themselves off an hour after being switched on. Diagnostics record far more detail and turn themselves off an hour later, so they cannot be left on by forgetting.
