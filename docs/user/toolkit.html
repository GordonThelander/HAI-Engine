Part 1 · Automation Map (HAM)

See what you have

Most hubs grow one rule at a time. After a few years, nobody remembers which rule turns on the Hall Light, or why the Front Door alert fires twice. Automation Map reads the hub and draws it for you.

  1. 1

    Scan the hub

    It looks at your devices and your apps: Rule Machine, webCoRE, HAI, and the other automation apps you have installed.

  2. 2

    Decode each app

    Decoders read each app's settings to learn three things: what starts it, what it checks first, and what it tells devices to do.

  3. 3

    Build the map

    Devices and rules become points on a map, joined by the links between them. Tap the Hall Light and you see every rule that touches it.

  4. 4

    Map dependencies

    It finds rules that control other rules, such as one that pauses another at night. It also shows hub variables that several rules share.

  5. 5

    Insights

    Insights point out things worth a look, like a device no rule uses. Room Manager groups it all by room.

    A daily scan is optional; "Assess now" runs one whenever you like.

  6. 6

    Works on its own

    You don't need HAI to use the map. It is simply the clearest view of your hub, whichever apps run your rules.

Part 2 · HAI Engine

Write and run rules

This is where you write new rules and run them. Write a rule yourself, ask AI to draft it, or let an assistant propose it. A person always puts it on the hub.

  1. 1

    The rule editor

    Rules are blocks in plain words: "When Front Door opens, if it is after sunset, turn on Hall Light." Device values show live as you build.

    Check tests a rule before it goes on the hub, and Run now tries it straight away. Drafts stay separate from what the hub runs. 24 starter patterns help you begin.

  2. 2

    The AI author

    Describe a rule in your own words and Claude drafts it in the editor. You read it, change it, and decide. Nothing goes live until you put it on the hub.

  3. 3

    MCP for AI assistants

    AI assistants and tools can read your hub and propose rules through HAI's MCP tools, such as hai_describe and hai_propose_rule. A person still approves each one.

  4. 4

    The runtime

    Each rule runs as its own small app on the hub. It survives restarts and keeps its own history, so you can see what it did and when. A watchdog checks that it is still running.

  5. 5

    Safety

    HAI checks every rule before it goes on. A disabled device gives a warning, not a block. Calls that change hub settings are guarded.

    Outside tools need an access key, and a Rotate button replaces it if you are ever unsure.

Part 3 · How they connect

See, write, run

The map shows the whole hub

Rules you write in HAI appear on the map beside everything else, so you can see what each one touches and what it depends on.

Every rule goes through the Engine

The Engine checks each rule, keeps the draft apart from the live version, and puts it on the hub as its own small app.

AI proposes, you decide

The AI author and MCP tools can only hand the Engine a draft. Putting it on the hub is always a person's choice.

The map keeps up with HAI

HAI publishes a list of what it can do, and Automation Map reads it to show what HAI supports.

Optional · HAI Migration (HMA)

Already have Rule Machine rules?

You don't have to move anything. Your Rule Machine rules keep working alongside HAI. If you do want to bring some across, the optional HAI Migration app copies them using Automation Map's scan. Each copy stays stopped until you have tested it, and one click puts Rule Machine back in charge.

What a moved rule gains: it reads in plain words, it is checked before it goes live, an AI helper can explain or change it for you, and it keeps its own history of what it did and when.
